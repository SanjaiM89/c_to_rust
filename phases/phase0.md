# Phase 0 — Scope and setup

**Date:** 2026-11-13 · **Exit gate:** C tests pass · toolchain versions recorded ·
local model smoke test passes · README documents everything

---

## Summary

Phase 0 is complete. The cJSON target is pinned at **v1.7.19** (`c859b25`), the C library
builds and **all 22 upstream C tests pass**, the full toolchain is installed and version-pinned
in `artifacts/toolchain_versions.txt`, and a **100-file fuzz seed corpus** is built from
upstream inputs plus 62 hand-written edge cases. The local model runs **fully on the GPU**
(37/37 layers offloaded, CUDA backend) at **72.7 tok/s** generation.

The significant finding of this phase is a **forced deviation**: no Anthropic API key exists
in this environment and the machine has no budget, so `claude-sonnet-5-5` / `claude-opus-5-5`
are unreachable. The main model was therefore moved onto the local GPU, and the candidate
choice was made **by measurement, not assumption** (§5): `Qwen3-4B-Instruct-2507-Q4_K_M` beat
`qwen2.5-coder-3b-instruct-q4_k_m` 3/4 vs 2/4 on compile rate, with 0 vs 4 `unsafe` blocks.

## Open risks

1. **No paid model.** The "main model" is a 4B local model. It is materially weaker than
   `claude-sonnet-5-5` at multi-file reasoning and long-context repair. Every Phase 3/5
   number must be read as *"what a 4 GB-VRAM local model achieves"*, not *"what an LLM
   achieves"*. This is a **hard limit of the experiment**, stated up front so it is not
   mistaken for a property of the method.
2. **No escalation path.** The brief escalates to Opus after 2 failed Sonnet repairs. There is
   no Opus. Replacement: 5 retries on the local model, then a **hand-written reference
   implementation** by me, which changes the authorship of those units — recorded per unit.
3. **CUDA vs Vulkan.** CUDA needed three Debian packages that were not pre-installed
   (`libcudart12`, `libcublas12`, `libcublaslt12`). The stock prebuilt tarball ships without
   them and silently reports `Available devices: (none)`. The Vulkan build works with no
   extra packages but lists the Intel iGPU first.
4. **`--parallel 1`** means the local server handles one request at a time. Batch phases will
   be serial. Throughput is adequate (72 tok/s) but wall-clock for a full translation pass
   is dominated by generation, not by the C build.
5. **cJSON_Utils excluded** from translation scope but required by 2 upstream C tests
   (`json_patch_tests`, `old_utils_tests`). The Rust port must reimplement the *behaviour*
   those tests exercise, or the Rust-side test suite will need a documented, narrower
   equivalent. **Not yet resolved — flagged for Phase 2.**
6. **Kani install is long-running** (it downloads its own toolchain on first use). If it
   cannot complete, Level 3 of the validation ladder degrades to Miri-only for Kani-covered
   functions, which is explicitly weaker evidence (see Phase 7 limits).

## Go / no-go

**GO** for Phase 1.

Justification: the C reference builds and its 22 tests pass; the toolchain is complete and
pinned; the seed corpus exists; the local model runs fully on the GPU with measured
throughput. The one deviation (local main model instead of a paid API) is documented, is
unavoidable given a $0 budget, and does not block any phase — it changes the *quality
ceiling* of Phase 3, not the *validity* of the evidence pipeline.

The thing that would have blocked the project — no usable model at all — was resolved by
finding that the opencode gateway's own free tier is sufficient to run the *entire* pipeline
locally on the GPU.
